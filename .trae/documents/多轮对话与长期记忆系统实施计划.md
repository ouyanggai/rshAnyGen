# 多轮对话与长期记忆系统实施计划 (Revised)

根据您的反馈，我已将计划细化为更具操作性的阶段，强调测试驱动和基础设施就绪性。

## 核心策略
- **测试驱动**: 每个 Phase 必须包含单元测试和集成测试。
- **渐进式交付**: 先稳固基础 (Token/Monitor)，再扩展功能 (Summary/Memory)。
- **降级策略**: 优先保证工作记忆，长期记忆和摘要可视情况降级。

## 详细实施步骤

### Phase 0: 基础设施与监控
**目标**: 确保 Embedding、队列和监控就绪。
1. **Embedding 服务集成**:
   - 在 `apps/orchestrator/services/llm_client.py` 中添加 `get_embedding_client`，复用 LangChain OpenAIEmbeddings。
2. **异步任务队列**:
   - 确认使用 Redis List (`rpush`/`blpop`) 作为轻量级队列。
3. **性能监控**:
   - 创建 `apps/shared/metrics.py`，记录 Token 消耗、API 延迟等指标。

### Phase 1: Token 预算管理与上下文构建
**目标**: 实现智能的 Token 分配，优化上下文利用率。
**预算策略**:
- **分配比例**: 长期记忆 (10%) : 摘要 (20%) : 工作记忆 (70%)。
- **降级策略**: 若长期/摘要层数据不足，剩余预算自动流转给工作记忆。
- **边界条件**: 最小工作记忆 1024 tokens 或 2 轮对话。

1. **Phase 1a: Token 预算管理**
   - 修改 `TokenCounter` 添加 `get_token_budget`。
   - **测试**: `tests/shared/test_token_budget.py` (验证不同模型下的预算计算)。
2. **Phase 1b: 上下文构建器改造**
   - 重构 `ContextBuilder` 使用动态预算。
   - **测试**: `tests/gateway/services/test_context_builder.py` (模拟不同预算下的上下文组装)。

### Phase 2: 智能摘要生成
**目标**: 自动检测主题切换并生成摘要，减少 Token 消耗。
**存储设计**: Redis List `session:summaries:{session_id}`。

1. **Phase 2a: 核心服务实现**
   - 实现 `TopicDetector` (基于 Embedding 相似度)。
   - 实现 `SummaryGenerator` (基于 LLM)。
   - **测试**: `tests/orchestrator/services/test_summary.py` (验证切分和摘要生成)。
2. **Phase 2b: 后台任务集成**
   - 创建 `BackgroundTaskProcessor` 消费 `queue:summary_tasks`。
   - 修改 `chat.py` 在响应完成后投递任务。
   - **测试**: 集成测试，验证对话后是否触发摘要生成。

### Phase 3: 实体记忆层
**目标**: 提取并存储关键实体信息。
**存储设计**: Redis Hash `entity:{id}` + ZSet 索引。

1. **实体提取与存储**
   - 实现 `EntityExtractor` (规则 + LLM)。
   - **测试**: `tests/orchestrator/services/test_entity.py` (验证从样例文本中提取实体)。

### Phase 4: 语义记忆与优化
**目标**: 长期记忆的去重与维护。
**存储设计**: Milvus (Vector) + Redis (Meta)。

1. **Phase 4a: 向量检索与去重**
   - 实现 `MemoryService`，集成 Milvus 客户端。
   - 实现基于向量相似度的去重逻辑。
   - **测试**: `tests/orchestrator/services/test_memory_dedup.py`。
2. **Phase 4b: 衰减与维护**
   - 实现 `MemoryScorer` (时间衰减算法)。
   - 添加定期维护任务。
   - **测试**: 验证评分计算和归档逻辑。
